# Лабораторная работа 1. Демон Disk monitor (вариант 20)

Демон отслеживает через inotify использование файлов в каталогах из конфигурационного файла.
Каждое событие (открытие, чтение, запись, создание, удаление, перемещение файла или папки)
записывается в syslog с facility `LOG_LOCAL0`, которую rsyslog направляет в отдельный файл.
Подкаталоги отслеживаются рекурсивно, в том числе созданные после запуска.

## Сборка

```bash
./build.sh            # результат: ./disk_monitor, промежуточные файлы удаляются
```

## Тесты

Все тесты запускаются в Docker, чтобы не трогать систему (демоны, сигналы, `/tmp`, `/dev/log`):

```bash
./run_tests.sh                 # все тесты
./run_tests.sh -L unit         # только unit-тесты
./run_tests.sh -L component    # только компонентные
./run_tests.sh -R Sighup       # по имени
```

| Каталог | Что проверяет |
|---|---|
| `tests/ut/` | классы по отдельности: разбор конфига, pid-файл и `/proc`, inotify-воркер, синглтон |
| `tests/ct/` | настоящий бинарник `disk_monitor` как чёрный ящик: демонизация, сигналы, pid-файл, сообщения в syslog |

Компонентные тесты подменяют `/dev/log` своим сокетом и читают, что демон пишет в журнал.
Вне контейнера (без переменной `DISK_MONITOR_IN_CONTAINER`) они пропускаются.

Для IDE (CLion) тесты включены по умолчанию (`BUILD_TESTS=ON`). GoogleTest берётся из системы
(`sudo apt install libgtest-dev`), а если его нет, скачивается при конфигурации CMake.

## Настройка журнала

```bash
sudo ./setup_logs.sh  # local0.* -> /var/log/disk-monitor.log
```

Без rsyslog сообщения можно смотреть в journald: `journalctl -t disk-monitor -f`.

## Конфигурация

Файл `disk-monitor.conf` в рабочей папке (или путь первым аргументом):

```
# комментарий
DIR=/tmp/disk-monitor-demo
DIR=relative/path      # относительно папки конфига
```

Перед первым запуском с примером конфига: `mkdir -p /tmp/disk-monitor-demo`.

## Запуск и управление

```bash
./disk_monitor                     # или ./disk_monitor /path/to/config.conf
kill -HUP  $(cat /tmp/disk_monitor.pid)   # перечитать конфиг
kill -TERM $(cat /tmp/disk_monitor.pid)   # завершить
tail -f /var/log/disk-monitor.log
```

Повторный запуск находит старый экземпляр по pid-файлу `/tmp/disk_monitor.pid`, проверяет его
через `/proc`, отправляет ему SIGTERM, дожидается завершения и записывает свой pid.

## Устройство

| Модуль | Назначение |
|---|---|
| `config/` | разбор конфига, приведение путей к абсолютным |
| `daemon/daemon` | синглтон демона: двойной fork, setsid, сигналы через signalfd, главный цикл poll |
| `daemon/pid_manager` | pid-файл, проверка процесса через `/proc`, остановка старого экземпляра |
| `worker/` | inotify: рекурсивные watch-и, разбор и запись событий |

Ограничения: если отслеживать каталог, в котором лежит сам лог-файл, демон будет
регистрировать собственные записи в журнал.
